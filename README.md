# 律动遗迹 · 右心房第一层节奏战斗

一个为两周小学期课程制作的 2D 顶视角像素节奏地牢游戏，暂定名为《律动遗迹》。项目使用 Godot 4.7.2 标准版与 GDScript：玩家依照遗迹深处“心核”的搏动战斗，击败窃取生命力量的怪物，最终修复心核并复苏凋亡的异世界森林。

## 当前状态

- 工程默认入口是第一层右心房的五房间可试玩流程：整备前厅 → 窃能幼体常规战斗 → 回响祭坛 → 窃能幼体与泥浆喷吐者混合战斗 → 静脉吸附者·泥鳃；Boss 击败后在 Boss 房中央开启传送门，靠近后按 `E` 进入第二层入口状态，不再额外创建没有玩法内容的传送房。四层最终流程仍在后续开发。
- 玩家在统一节拍上按格移动、相邻攻击或原地蓄力；蓄力最多一层，下一次成功命中额外造成 1 点伤害。
- 连续 4 次有效行动会获得一层节奏护盾；它可以把一次 `±120 ms` 正常窗口外、但不超过 `±200 ms` 的输入吸附回拍点。以上都是待用户试玩的原型参数，不是最终平衡。
- 已实现玩家先行动、敌人后行动、窃能幼体两拍追击/攻击（首拍举刀或蓄势，下一拍执行）、泥浆喷吐者四拍定点发射、泥浆弹逐拍移动、同拍迎击弹刀、生命/死亡、空格或 `Esc` 暂停、暂停面板“继续游戏/返回标题”、左 Shift 按拍蓄力、`E` 交互传送、穿甲音波/共鸣护盾局内回响，以及泥鳃的 3×3 实际占格和“血沉泥浆 → 横扫蓄力 → 三格扇扫 → 安全后摇”四拍循环。怪物方向提示、泥浆弹和危险格不再使用矩形外框或连接线，玩家、两类怪物、Boss、弹体与危险格均按可见轮廓对准逻辑格心。原向心吸附/全屏拉拽已删除。穿甲音波把普通方向攻击延伸到前方第二格（中间格为空时），共鸣护盾把获得节奏护盾的临时门槛降到 3 次连续有效行动；两项具体平衡仍待试玩确认。第一层 Boss 不改变全局 BPM；132 BPM 仅为旧接口兼容常量，不在当前流程生效。
- 当前本地 MVP 已引用房间背景、玩家/敌人/Boss atlas、hurt/death 单帧、攻击特效、心核、祭坛、回响和 HUD 图标；行动格已校准到背景完整的 11×6、60px 地砖区，不再绘制绿色格线，角色与各动作状态都落在实际地砖中心。出口已从逻辑棋盘边缘移到背景右墙中央，触发后会播放生成的四帧出口门特效、玩家冲门、门口能量爆发、扫屏光条与新房落地动画；清房“能量回流”只在击杀最后一只怪物时出现一次。弹刀接入生成的四帧无文字特效，并保留双方攻击姿态、交叉刀光、短暂停顿、火花/冲击环、震屏和后坐表现；下方中央音符轨道提前三拍进入，奖励卡文字居中，选择数字独占最下方一行。
- 默认启动先进入开始页：`开始游戏`、`设置`、`退出游戏`。设置页可调整主音量（0–100%）、谱面延时（-200–+200 ms）并逐项重新绑定移动、蓄力、暂停和传送交互键位；设置保存到 `user://mvp_settings.cfg`，不会改写项目源码配置。当前开始页/设置页的装饰图片仍使用程序绘制占位，缺口已登记在 `assets/generated/bhai/GENERATION_QUEUE.md`。
- 节拍音频提示、下落音符和输入判定共用同一个拍点时间基准；音频 click 会在输出延迟补偿后请求播放，谱面延时同时移动视觉与判定。输入归属采用相邻拍中点保护：上一拍已经结束后才到达的慢输入不会锁住下一拍，下一拍仍可正常命中；超出当前判定窗的本拍输入仍按 miss 处理。
- 企业生成素材的公开再分发授权尚未确认，因此相关原图、派生图和本地引用均不得直接推送到公开仓库。节拍提示音继续使用程序生成的简单 click 占位；事件音效和 BGM 候选已清理，等待用户另行指定音频任务。MVP UI 已接入可公开分发的 Fusion Pixel 12px 简体中文比例像素字体，来源与许可证见 [`assets/fonts/README.md`](assets/fonts/README.md)。
- 开题答辩草模仍保留在 `scenes/main.tscn` 和 `scripts/main.gd`，但不再是工程默认入口。
- 已配置 macOS DMG 与 Windows x86_64 EXE/PCK 导出预设。
- Windows 正式构建由用户在另一台 Windows 电脑上做实机测试，不使用虚拟机。

## 打开项目

在 Godot 项目管理器中导入本目录，或在终端执行：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --editor --path "/Users/hoshitsuki/大二上/小学期程序实践"
```

如果 Godot 弹出“文件已在 Godot 外部修改”的提示，请选择“从磁盘重新加载”，以读取最新的 `project.godot` 输入配置；不要选择“忽略外部修改”。

直接运行当前正式原型：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --path "/Users/hoshitsuki/大二上/小学期程序实践"
```

操作方式：

- `WASD` 或方向键：在下落音符接近轨道底部判定线时输入；指向空地会移动一格，指向相邻敌人会攻击，获得穿甲音波后可隔一个空格攻击第二格敌人。
- `左 Shift`：在有效拍点原地蓄力；无输入才是普通等待。
- `空格` 或 `Esc`：暂停或继续游戏；暂停面板提供“继续游戏”和“返回标题”，暂停期间节拍、敌人和动作动画都会冻结，继续时从原拍点进度恢复。
- 每拍最多接收一次输入；玩家行动结算后，仍存活的窃能幼体每两拍完成一次动作：第一拍锁定并以格心箭头配合自身举刀/蓄势，第二拍才攻击或移动。攻击前摇期间移开会让敌人挥空；在执行拍朝举刀敌人攻击会触发弹刀，双方不扣血并同时后弹，接触反馈不显示“弹刀”浮字。泥浆喷吐者固定在原地按四拍循环发射；泥鳃 Boss 使用独立四拍时间线，实际占据中央 3×3 格，横扫从本体外缘向前延伸 3 格，第四拍为可近身攻击的后摇。
- 奖励房按 `1` 或 `2` 选择一枚仅在本局生效的回响：`穿甲音波` 让普通攻击延伸至前方两格，`共鸣护盾` 将节奏护盾门槛从 4 连击临时降至 3 连击。
- `E`：Boss 击败后，靠近 Boss 房中央传送门进入下一层入口状态。
- `R`：随时重新开始；结算界面也可按 `Enter` 重开。胜负画面只显示结局叙事与下一步操作，不显示开发期的有效行动/失拍统计。

旧单房原型回归：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless \
  --path "/Users/hoshitsuki/大二上/小学期程序实践" \
  --script res://tests/proto_001_smoke.gd
```

成功时会输出 `PROTO_001_SMOKE_OK`，并覆盖节拍、判定、单拍输入锁、移动、攻击、敌方回合、胜负、重开和场景加载。

五房间 MVP 回归：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless \
  --path "/Users/hoshitsuki/大二上/小学期程序实践" \
  --script res://tests/mvp_smoke.gd
```

成功时会输出 `MVP_SMOKE_OK`，覆盖第一层五房路线、窃能幼体两拍战斗、泥浆喷吐者四拍弹体、泥鳃四拍 Boss 循环、Boss 房中央传送门与 E 交互终点、无文字弹刀、背景地砖对齐、地图心核/角色/结算心核的实际视觉重心、右墙出口、动画转场、空格暂停/左 Shift 蓄力、单次清房反馈、正式 HUD、Boss 顶部血条、下落式节奏轨道、居中奖励卡、叙事式结算、90 BPM、节奏护盾、动作时间线和转场重开安全。

`tests/mvp_capture.gd` 可在 macOS 显示驱动下复现 `start`、`vertical`、`action`、`clash`、`charge`、`pause`、`transition`、`reward`、`mud`、`boss`、`death` 和 `victory` 十二种 960×540 画面检查状态；`start` 展示位于完整棋盘视觉中心的心核，`mud` 展示无框泥浆弹/危险格，`boss` 展示泥鳃 3×3 占格、无框扇面和明显横扫蓄力，`death/victory` 展示视觉重心居中的结算心核。该脚本不替代用户真实键盘试玩；不要用 `--headless` 运行，脚本会明确提示并以非零码退出。

## 目录

- `scenes/`：Godot 场景。
- `scripts/`：GDScript 源码。
- `tests/`：可独立运行的 headless 回归检查。
- `assets/`：像素图、瓦片、音频、字体等项目资源。
- `开发记录/`：决策、日志、问题、环境和里程碑证据。
- `游戏策划案/`：可持续修改的游戏内容工作稿。
- `设计文档/`：已经确认的玩法、世界观和后续系统设计。
- `交付/`：已完成阶段的最终交付压缩包。
- `builds/`：按需生成的本机构建输出，不纳入 Git。

## 导出

Godot 菜单中使用 `项目 → 导出`，选择 `macOS` 或 `Windows Desktop` 预设。默认目标分别为：

- `builds/macos/RhythmDungeonPrototype.dmg`
- `builds/windows/RhythmDungeonPrototype.exe` 与同目录 PCK

正式构建前先确认当前 Git 工作区状态，并在 `开发记录/01-环境与构建.md` 中登记版本与测试结果。
