# 项目决策

更新时间：2026-08-24

## 已确定

- 项目周期约两周。
- 课程对引擎和运行平台的自由度较高。
- 评分形式以汇报答辩为主，因此开发过程和关键节点需要留下可追溯记录。
- 游戏方向为较完整的 2D 像素风音乐节奏闯关游戏，参考《节奏地牢》的“节拍与行动结合”思路，但不复刻其完整系统。
- 选择 Godot 标准版与 GDScript 作为开发路线，不使用 Godot .NET/C# 版。
- 本机开发和主要演示版本面向 macOS；希望同时提供能在常见 Windows 电脑运行的 x86_64 版本。
- Windows 实机测试由用户在另一台 Windows 电脑上完成，不准备 Windows 虚拟机。
- 每个小分任务完成后及时同步开发日志和项目记忆；有复用价值的问题必须记录现象、原因、解决方法和验证。
- 对边界独立、体量较大且可单独验收的合适任务，主动调用 `terra_worker` 并由主线程复核。
- 长流程按阶段拆分到多个新会话；根目录 `RESUME.md` 作为统一恢复入口，新会话先恢复阶段、事实源、未验证风险和下一安全动作。
- 用户当前先进行游戏开发的初步了解；在用户明确进入正式开发前，不提前实现节拍、移动或其他正式玩法。

## 当前范围边界

- 先完成节拍、移动、攻击、敌人与关卡胜负组成的单一可玩闭环。
- 前期使用占位素材，核心玩法稳定后再替换像素美术和音频。
- 不在第一版加入联网、复杂装备系统、程序化大地图或大量关卡。

## 仍需后续确定

- 游戏名称与一句话核心循环的最终表述。
- 节拍失误的惩罚方式，以及移动和攻击是否共用同一拍。
- 最终关卡数量、敌人数量和素材来源。
- 答辩时使用现场演示、录屏还是两者同时准备。
