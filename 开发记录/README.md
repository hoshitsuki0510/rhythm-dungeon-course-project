# 开发记录

本目录保存课程汇报和答辩需要的关键证据，不保存 Godot 自动生成的缓存。

## 需要记录什么

- 为什么选择某个玩法、引擎或实现方案。
- 每个可玩版本增加了什么，以及当时能够演示什么。
- 遇到的重要问题、原因、解决办法和验证结果。
- 关键画面、短录屏、性能数据和跨平台测试结果。
- 被放弃的方案及原因，避免答辩时只能展示最后成品、无法说明过程。

## 文件分工

- `00-项目决策.md`：目标、范围和重要技术决定。
- `01-环境与构建.md`：引擎、导出模板、macOS/Windows 构建及测试记录。
- `开发日志.md`：按日期追加的简短工作记录。
- `问题记录.md`：可复用问题的现象、原因、解决方法、验证和遗留风险。
- `里程碑/节点记录模板.md`：完成重要节点时复制一份，按 `YYYY-MM-DD-节点名称.md` 命名。

## 建议保留的五个关键节点

1. 节拍信号能够稳定触发。
2. 玩家能够按格移动，并判断是否踩准节拍。
3. 第一种敌人、攻击、受伤和死亡形成闭环。
4. 第一个关卡能够从开始玩到胜利或失败。
5. macOS 和 Windows 构建均在真实设备上完成测试。

每次记录保持简短，但要尽量附上对应提交、截图、录屏或构建文件路径。

## 强制同步规则

- 每完成一个小分任务，立即更新开发日志，并把稳定进度同步到项目记忆。
- 遇到具有复用价值的问题时，及时补充问题记录，不能只在聊天中保留解决方法。
- 适合独立验收的大型只读或隔离任务应使用 `terra_worker`，返回结果由主线程复核。
- Windows 实机测试在用户的另一台 Windows 电脑上完成，不为本项目准备虚拟机。
