# 节点：Godot 工程与 Git 初始化

- 日期：2026-08-24
- 工程基线提交：`eb5423e`（`chore: initialize Godot project`）
- 构建版本：Godot `4.7.2.stable.official.ed1daf0bf`

## 本节点目标

建立一个可运行、可版本控制、能够分别导出 macOS 和 Windows 构建的最小工程基础线；不提前实现正式节奏玩法。

## 实现内容

- 创建 `project.godot`、主场景 `scenes/main.tscn` 和入口脚本 `scripts/main.gd`。
- 使用 Compatibility 渲染器、960×540 基准分辨率和像素图 nearest 过滤。
- 建立素材、场景、脚本、开发记录和构建输出边界。
- 配置 macOS DMG 与 Windows x86_64 EXE/PCK 导出预设。
- 初始化 Git `main` 分支、忽略 Godot 缓存和构建产物，并创建工程基线提交。

## 验证结果

- Godot 首次资源扫描完成，主场景与脚本无界面运行并输出 `INIT_SMOKE_OK`。
- Windows 成功导出 EXE/PCK，EXE 静态识别为 PE32+ x86-64；运行验证等待用户在另一台 Windows 电脑完成。
- macOS 成功导出 DMG；镜像校验有效，应用为 Universal 2 双架构，签名检查有效，挂载后的应用实际运行成功。
- 达到本节点完成标准。

## 问题与取舍

- 首次 Universal macOS 导出因 ETC2/ASTC 纹理导入未启用而失败。
- 在工程渲染设置中启用该选项后重试，DMG 完整通过验证。
- 初始化首页只使用文字与纯色，不引入临时第三方素材，避免版权和资源结构在玩法确定前固化。

## 答辩可讲内容

项目没有直接从大量功能开始，而是先建立可运行、可回退、可跨平台导出的工程基线。初始化阶段通过一次真实导出暴露了 macOS ARM 模板的纹理压缩要求，并用配置修改和独立验证闭环解决。Git 将后续每个小功能与这条干净基线分开，便于解释开发过程和定位问题。
