# 节点：跨会话恢复机制

- 日期：2026-08-24
- 对应 Git 提交：待本节点提交后以 Git 历史为准
- 验收状态：`EVIDENCE_REPORTED`

## 本节点目标

为长达多个会话的游戏开发流程建立统一恢复入口，使新会话不依赖旧聊天，也能识别当前阶段、已验收基线、未验证风险和下一安全动作。

## 实现内容

- 在根目录建立 `RESUME.md`，参考 2026 数学建模国赛项目的恢复骨架。
- 定义事实源优先级、七步恢复顺序和五项恢复摘要。
- 建立阶段路线图和子任务登记表，区分 `DRAFT`、`EXECUTING`、`EVIDENCE_REPORTED` 和 `ACCEPTED` 等状态。
- 将恢复规则写入 `AGENTS.md`，并在根 `README.md` 和开发记录索引中建立入口。
- 明确当前处于 `LEARN-001`，将 `LEARN-001A` Godot 基础概念速览设为默认下一微任务，不修改正式玩法代码。

## 验证结果

- 本地结构检查确认 `RESUME.md` 包含 12 个必需章节，所有关键相对路径存在，根 README 恢复链接指向正确。
- `git diff --check` 通过，新增恢复文档未发现 GitHub 令牌或私钥模式。
- 调用无历史 `terra_worker` 做独立只读冷启动；它不读取旧聊天或项目记忆，仅凭仓库即正确输出五项恢复摘要。
- Terra 正确识别 `LEARN-001`、三项已验收基线、Windows 尚未实机运行的风险，以及“不得提前写正式玩法代码”的边界，结论为 PASS。

- 早期文件保留了“下一步制作节拍/移动原型”的历史表述。不篡改历史记录，而是在 `RESUME.md` 明确这些旧建议已被当前了解阶段取代。
- 当前已通过无历史代理模拟，但用户尚未在一个真实新会话中完成恢复，因此不提前标记为 `ACCEPTED`。

## 答辩可讲内容

项目将长流程拆成可验收子任务，并使用恢复入口和证据优先级防止新会话重复工作或把计划误当成完成事实。独立无历史验收表明，仅依赖仓库即可恢复到正确阶段，同时保留 Windows 实机验收等未完成边界。
