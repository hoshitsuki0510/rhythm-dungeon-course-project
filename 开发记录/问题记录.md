## 2026-08-24：Godot 导出模板大文件经代理反复中断

- 现象：Godot 项目管理器处于离线模式；约 1.22 GB 的官方完整导出模板包通过本机代理下载时，单次连接多次以 `curl: (18) Transferred a partial file` 中断。
- 影响：无法直接从编辑器按平台下载模板；单次普通下载不能可靠完成。
- 原因：本机代理能够连接官方站点，但长连接会周期性截断；Godot 项目管理器当时未处于在线模式。
- 解决方法：改用 Godot 官方 GitHub Release 地址，多次使用 HTTP 断点续传；完成后以官方发布清单中的 SHA-512 校验整个模板包，只提取 macOS、Windows x86_64 与 ICU 文件。
- 验证：模板包最终大小为 1,281,349,702 字节，SHA-512 与官方值完全一致，压缩包完整性测试无错误；安装后的版本标记为 `4.7.2.stable`，与编辑器匹配。
- 遗留风险：未来升级 Godot 时，导出模板必须同步升级并重新校验；不能混用不同版本模板。

## 2026-08-24：Universal macOS 导出要求 ETC2/ASTC 纹理导入

- 现象：首次执行 macOS 导出时，Godot 拒绝导出并提示：禁用 ETC2 ASTC 纹理格式时无法为 Universal 和 arm64 导出。
- 影响：Windows x86_64 构建可以正常生成，但 macOS DMG 无法生成，跨平台初始化验收不完整。
- 原因：工程使用 Universal 2 macOS 模板，其中包含 `arm64`；新建的空工程尚未启用 ETC2/ASTC VRAM 纹理导入设置。
- 解决方法：在 `project.godot` 的 `[rendering]` 中加入 `textures/vram_compression/import_etc2_astc=true`，随后重新导入工程并执行 macOS release 导出。
- 验证：DMG 成功生成并通过 `hdiutil verify`；只读挂载后，应用为 `arm64 + x86_64` 双架构，代码签名有效，导出的应用实际无界面启动并输出 `INIT_SMOKE_OK`。
- 遗留风险：以后若更换渲染器或纹理压缩配置，需要同时复测 macOS 与 Windows 正式构建，不能只以编辑器运行正常作为依据。
